# Tuxano Booking 2.3.1 — email branding and vehicle availability

Owner request: 26 October 2026 (Asia/Dhaka). Direct update/testing of the supplied WordPress site is authorized. Keep 2.2.1 for rollback; 2.3.0 is retained as the initial feature build.

Customer/admin receipts now use the thank-you page's serif headings, navy branding, request/date banner, journey/vehicle/contact sections and itemized estimate. Email headers use **#0a121f**. Settings → Email supports a native Media Library image or public image URL; an empty value uses the existing bundled wordmark at the current plugin asset URL. Branding is private configuration and does not invalidate fares.

Confirmed/Cancelled/Completed transitions automatically notify the customer once per committed revision when customer notifications are enabled. Confirmation includes thanks, request ID, date/time, pickup/drop-off, vehicle and the saved estimate. Cancellation is a short apology/ID/help message; completion thanks the customer and welcomes the next journey. Ordinary edits retain optional detailed revision emails. Initial receipts and update retries keep separate durable transport leases. No notification is sent merely by upgrading.

Vehicle selection and Continue now fetch fresh, session-bound availability. Pending/reviewing requests require an acknowledgement warning; confirmed bookings block the same vehicle and exact pickup minute. A different vehicle remains bookable. Cancelled/completed records release their slot. Server-side final submission and admin confirmation/rescheduling recheck the derived UTC slot under a short database write lease; a unique nullable slot key independently prevents double confirmation. Old local pickup data, payload, status, history and accepted prices are retained while additive indexes are backfilled. Invalid/unfinished confirmed schedules fail closed. Popup generations prevent stale replies; dialogs work on phones and inside tall shortcode iframes.
