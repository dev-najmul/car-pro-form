# WordPress implementation contract

Plugin: `tuxano-booking`, version 2.0.1, namespace `Tuxano\Booking`, WordPress >=6.6 / PHP >=7.4. Existing static form stays supported. Build copies shared root frontend and assets into plugin `public/`; do not duplicate tracked image files.

## Runtime and UI
- One top-level **Tuxano Booking** menu: dashboard, submissions (custom private table, detail/status/admin notes, search/status/date filters/pagination), vehicles (private CPT `tuxano_vehicle` with native CRUD and taxonomy `tuxano_collection`), pricing, settings.
- Shortcode `[tuxano_booking]` embeds an accessible same-origin iframe, isolating existing design from theme CSS. `?tuxano_booking_form=1` serves the standalone document. Parent resize bridge validates origin/window. Shared app supports optional `globalThis.TuxanoBooking` runtime; static mode keeps its current behavior.
- WordPress bootstrap does POST `/tuxano-booking/v1/session`, then imports app. Response `{token, vehicles, settings, maps:{browserKey,browserConfigured:true,routesConfigured:true,providerMode:'remote',routeEndpoint:restUrl+'route'}, restUrl}`. POSTs use `X-Tuxano-Session: token`, JSON, same-origin credentials; logged-in REST requests also use `X-WP-Nonce` supplied by frame config. Session response is private/no-store.
- `vehicles`: `{id,name,display,capacity,luggageCapacity,image,models:[],features:[],category,categoryDescription,tariff:{base,perMile,perDrivingMinute,minimum,perWaitingMinute,hourly}}`; image absolute URL; id is string WP post ID. Categories grouping must be dynamic. Defaults seed six current vehicles/categories on activation, once, editable.
- `settings` public: `{currency,currencySymbol,meetPrice,firstSeatPrice,additionalSeatPrice,defaultGratuity,companyName,supportEmail,supportPhone,website,termsUrl,privacyUrl,maxStops,minHours,maxHours}`. Private keys/admin email never returned. Browser Maps key intentionally public.
- Route POST accepts `{origin:{placeId}|{latitude,longitude},destination:...,stops:[]}`. Returns `{distanceMeters,durationSeconds,provider:'google',calculatedAt,quoteToken}`. Google calls only on PHP server using private key, fixed Google endpoint, bounded timeouts, same route settings as static. Quote token links verified route to session for 15min.
- Booking POST `/bookings` accepts `{booking: state,quoteToken,requestKey,website:''}`. `booking` matches root app state schema. Server validates locations against quoted origin/destination/stops, time, vehicle/capacity, billing/passenger/consent/options; recomputes all fares/extras/gratuity from stored tariffs and route metrics, never client totals. Returns `{requestId,pricing,route}` after durable save. `pricing`: transportation,carCost,boosterCost,seats,meet,percent,tip,total,currency. Failures use WordPress REST errors `{code,message,data:{status}}`. Quotes carry pricing revision; changed settings require refreshed quote. Idempotency key prevents duplicate bookings/emails on retry.
- Server-side session/origin checks, bounded per-session/IP rates, honeypot, body limits; no anonymous submission-reading API. Admin actions require manage_options + nonces. Keys write-only in admin; blank preserves, explicit clear removes. WordPress options not autoloaded. No keys/passwords in source/logs/release.

## PHP ownership/interfaces
Root implements plugin entry, Database.php, Rest.php, Notifications.php, Frontend.php, build/test/deploy integration. All classes static methods; include files from entry.

Agent data implements **Settings.php, Vehicles.php, Pricing.php** only:
- Settings::defaults(), get() -> merged complete settings; save(array) -> true|WP_Error; public_data(); revision() -> hash tariffs/settings; secrets via get()['browser_key'], get()['routes_key']; keys `admin_email`,`email_customer` bool,`email_admin` bool,`retention_days` int (0 disables automatic cleanup), public keys snake_case storage, public_data camelCase response above. Notification optional sender_name/from_email defaults WP website-domain address; do not permit header injection.
- Vehicles::register(), seed(), all(bool $active_only=true) -> frontend array above, find(string $id) -> array|null. CPT publication means active; drafts disabled. Metadata fields editable through nonce+capability-checked native post meta box, category native taxonomy. Seed exact original 6 tariffs/descriptions. Metadata tariff values finite nonnegative capped, capacities 1..100, media attachment/photo URL HTTPS/relative plugin URL only. Category/name/descriptions escaped at output.
- Pricing::calculate(array $vehicle,array $route,array $booking,array $settings) -> pricing array. Match shared pricing formulas/rounding, waiting sums. throws InvalidArgumentException for invalid values. Include currency, fare components. WP cents consistent JS.

Agent admin implements **Admin.php, admin.css, admin.js** only:
- Admin::register() hooks menus/admin_post handlers. Refer Settings/Vehicle methods above.
- Database::table() returns table name; Database::find(int $id) -> associative row|null; Database::listing(array $filters) -> `{items,total}` with filters search,status,from,to,page,per_page; Database::counts() -> counts total + statuses; Database::update(int $id,array $changes) -> bool|WP_Error (only status,notes); Database::delete(int $id) -> bool; Database::ST​ATUSES=['new','reviewing','confirmed','cancelled','completed']; rows include id,reference,status,created_at,pickup_at,customer_name,customer_email,vehicle_name,total,currency,payload,pricing,route,notes,customer_mail,admin_mail. JSON columns decoded by find() only; listing scalar rows. Notification statuses pending/accepted/failed.
- Notifications::send(int $id,bool $retry=false) sends only pending/failed recipient, updates statuses. Admin resend nonce action authorized. Email delivery acceptance not inbox guarantee.
- Settings form handles write-only keys; Pricing page edits global extra rates and default gratuity, links vehicle-specific tariff editing. Settings::save merges only submitted keys and validates. Admin notes/status/delete and CSV optional only safely gated; do not add unsolicited paid addons.

Agent frontend owns root **app.js, maps.js, pricing.js**, plus plugin **assets/bootstrap.js, assets/embed.js**. Maintain static behavior and security, dynamic admin-configured fleet/categories/all pricing/branding, real POST and returned receipt. No WP iframe theme scoping needed. Root will build/copy styles/assets/shared JS.

## Verification / delivery
Use isolated Docker WordPress + MariaDB for integration, PHP lint, deterministic mocked provider tests + actual Google route tests. Live install only supplied dedicated test site; preserve existing pages/plugins/settings. Upload ZIP and create a separate booking test page, do not overwrite site home page. Use latest credentials from user privately; never track them. Existing Google keys reused through ignored local secrets. Notifications may be intercepted in local test mail transport; actual mail acceptance/delivery reported distinctly. All implementation decisions and remaining limits go in project.md. Production-oriented code does not imply a claim of absolute security certification.
